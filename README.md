# Constrained RL for SLA-Aware MAC Scheduling

Reference-anchored constrained reinforcement-learning experiments for heterogeneous downlink MAC scheduling with eMBB and latency-sensitive traffic.

This repository contains the exact experiment implementation and reproducibility outputs for the evaluated configuration. It includes strong non-learning baselines, reference-anchored PPO ablations, heterogeneous traffic/channel scenarios, matched-seed evaluation, and packet-level latency metrics.

## Repository contents

```text
.
├── run_experiments.py        # main training/evaluation entry point
├── mac_env.py                # packet/queue-level environment
├── baselines.py              # PF/EDF and strong service-aware baselines
├── hierarchy.py              # reference class-budget controller
├── shield.py                 # emergency URLLC protection layer
├── pdppo.py                  # PPO, critics, and primal-dual updates
├── requirements.txt
├── scripts/
│   ├── run_smoke.ps1
│   └── run_full_experiments.ps1
└── results/
    ├── config.json           # exact final experiment configuration
    ├── raw_results.csv       # per-seed/per-scenario results
    ├── summary.csv           # aggregated results
    ├── training_history.csv  # rollout-level training history
    └── figures/              # figures generated by the experiment runner
```

The `src/` directory contains a duplicate snapshot of the core Python modules for convenient archival organization. The top-level copies are retained because the experiment runner imports them directly.

## Full evaluated experiment

The complete configuration uses 800,000 training steps per RL model, five independent seeds, seven evaluation scenarios, and matched evaluation seeds across methods.

```powershell
python run_experiments.py --profile paper --device cuda --methods PF EDF DeadlineAwarePF SLAWeightedPF ReferenceClassPF DemandAwareClassPF unconstrained fixed_penalty single_constraint multi_constraint --out results_final
```

If CUDA is unavailable, replace `--device cuda` with `--device cpu`.

## Methods

Non-learning baselines:

- `PF`
- `EDF`
- `DeadlineAwarePF`
- `SLAWeightedPF`
- `ReferenceClassPF`
- `DemandAwareClassPF`

RL ablations:

- `unconstrained`
- `fixed_penalty`
- `single_constraint`
- `multi_constraint`

The learned policy outputs bounded residual corrections around a state-aware reference controller rather than directly learning the complete per-UE allocation from scratch.

## Evaluation scenarios

The evaluated scenario set includes:

- nominal heterogeneous traffic/channel conditions,
- eMBB load surge,
- edge-user fading,
- bursty latency-sensitive traffic,
- mixed dynamic stress,
- a held-out localized hotspot,
- tighter latency requirements.

## Important reproducibility note

The evaluated implementation intentionally preserves the exact burst-stress behavior used to generate the included results. The scenario burst-severity parameter participates in more than one part of the URLLC load-generation process: it affects the burst process and packet inter-arrival behavior. It should therefore be interpreted as a **compound burst-stress parameter**, not as a literal multiplicative increase in offered traffic.

Do not alter this behavior when attempting to reproduce the included CSV results.
